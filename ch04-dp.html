part 1dynamic programming

How to Compute the Value Function 왜 DP?

p.2

정책 \(\pi(a\mid s)\), 전이 \(p(s'\mid s,a)\), 보상 \(r(s,a,s')\)를 알면 벨만 방정식이 연립방정식이 되고, 풀면 \(v_\pi(s)\)가 나와요. 그런데 큰 문제에서 연립방정식을 푸는 건 너무 어려워요 — \(O(|\S|^3)\).

p, r, π→Bellman Equation→Simultaneous Equations→\(v_\pi(s)\)

그래서 대신 쓰는 것이 동적 계획법(Dynamic Programming, DP).

Dynamic Programming 동적 계획법

p.3 – 4

DP는 다음 세 성질을 이용해 복잡한 문제를 푸는 방법이에요.

  1. Substructure (부분 구조): 원래 문제를 더 작은 부분 문제들로 쪼갠다.
  2. Table structure (테이블 구조): 각 부분 문제의 해를 테이블에 저장해 여러 번 재사용한다.
  3. Bottom-up computation (상향식 계산): 테이블을 이용해 작은 문제의 해를 합쳐 더 큰 문제를 풀고, 결국 원래 문제의 해에 도달한다.

예시: 피보나치 수

슬라이드의 재귀 버전 (같은 값을 중복 계산 — 지수 시간)

def Fibonacci(n):
    if n <= 1:
        return 1
    else:
        return (Fibonacci(n-1) + Fibonacci(n-2))

DP 버전 (테이블 + 상향식 — 선형 시간)

def fib_dp(n):
    table = [1, 1]            # 테이블
    for i in range(2, n+1):  # bottom-up
        table.append(table[i-1] + table[i-2])
    return table[n]

Evaluate Value Function using DP

p.5

\(k\)-스텝까지만 본 기대 리턴을 \(V_k\)라고 하면:

\[V_k(s) = \E_\pi\Big[\sum_{i=0}^{k-1} \gamma^i R_{t+1+i} \;\Big|\; S_t = s\Big]\]
\[V_k(s) = \sum_a \sum_{s'} \pi(a\mid s)\, p(s'\mid s,a)\big[r(s,a,s') + \gamma V_{k-1}(s')\big], \qquad \lim_{k\to\infty} V_k(s) = v_\pi(s)\]

표기: 반복하면서 계산 중인 추정치는 대문자 \(V_k\), 진짜 가치함수는 소문자 \(v_\pi\) (슬라이드와 같은 표기).

\(V_k\)는 DP의 세 성질을 만족해요:

  • Substructure: \(k\)-스텝 기대 리턴 = 보상 + 다음 상태에서의 \((k-1)\)-스텝 기대 리턴
  • Table structure: \(V_{k-1}(s')\)는 한 번 계산되면 \(s'\)로 전이할 수 있는 모든 상태 \(s\)가 재사용
  • Bottom-up: \(V_0 \equiv 0\)에서 시작해 \(V_1, V_2, \dots\)를 계산. 각 sweep은 \((k-1)\)-horizon 테이블로 \(k\)-horizon 문제를 정확히 품

Bellman Expectation Operator is Contraction Mapping

p.6 – 7
theorem

\((\R^{|\S|}, \|\cdot\|_\infty)\)에서 벨만 기대 연산자 \(T^\pi: \R^{|\S|}\to\R^{|\S|}\)는 축약사상이다:

\[\|T^\pi v - T^\pi v'\|_\infty \le \gamma\, \|v - v'\|_\infty, \quad \forall v, v'\]
proof
\[\begin{aligned} |T^\pi v(s) - T^\pi v'(s)| &= \big|\E_\pi[R_{t+1} + \gamma v(S_{t+1}) \mid s] - \E_\pi[R_{t+1} + \gamma v'(S_{t+1}) \mid s]\big| \\ &= \big|\gamma\, \E_\pi[v(S_{t+1}) - v'(S_{t+1}) \mid s]\big| \\ &\le \gamma\, \E_\pi\big[|v(S_{t+1}) - v'(S_{t+1})| \mid s\big] \\ &\le \gamma\, \E_\pi\big[\|v - v'\|_\infty \mid s\big] = \gamma\, \|v - v'\|_\infty \end{aligned}\]

모든 \(s\)에 대해 성립하므로 \(\|T^\pi v - T^\pi v'\|_\infty \le \gamma \|v - v'\|_\infty\). 즉 \(T^\pi\)는 \(\gamma\)-축약사상. \(\blacksquare\)

(3장의 최적 연산자 증명과 달리 max가 없어서 보조정리 없이 바로 됨!)

바나흐 고정점 정리 다시 소환완비 공간 + 축약사상 ⇒ 유일한 고정점이 존재하고 반복하면 수렴. 벨만 기대 방정식은 고정점 \(v_\pi\)를 정의하므로, \(V_k = T^\pi V_{k-1}\)을 반복하면 \(\lim_{k\to\infty} V_k = v_\pi\).

Iterative Policy Evaluation 반복적 정책 평가

p.8
  • 문제: 주어진 정책 \(\pi\)를 평가하기 (= \(v_\pi\) 구하기)
  • 해법: 벨만 기대 백업을 반복 적용
  • \(V_1 \to V_2 \to \cdots \to v_\pi\)
  • 동기식(synchronous) 백업 사용:
    • 매 반복 \(k+1\)마다
    • 모든 상태 \(s \in \S\)에 대해
    • \(V_k(s')\)로부터 \(V_{k+1}(s)\)를 갱신
    • 여기서 \(s'\)은 \(s\)의 후속 상태
# Iterative Policy Evaluation (동기식)
V = [0] * n_states
for k in range(max_iter):
    V_new = [0] * n_states
    for s in states:
        V_new[s] = sum(pi[s][a] * p[s][a][s2] * (r[s][a][s2] + gamma * V[s2])
                       for a in actions for s2 in states)
    if max(abs(V_new[s] - V[s]) for s in states) < theta: break
    V = V_new

part 3policy iteration

How to Improve a Policy 정책 개선

p.19

정책 \(\pi\)가 주어지면

  1. 정책을 평가: \(v_\pi(s) = \E[R_{t+1} + \gamma R_{t+2} + \cdots \mid S_t = s]\)
  2. \(v_\pi\)에 대해 그리디하게 행동하여 정책 개선: \(\pi' = \text{greedy}(v_\pi)\)
  • 작은 FrozenLake에서는 개선된 정책이 바로 최적이었다: \(\pi' = \pi_*\)
  • 일반적으로는 평가/개선을 여러 번 반복해야 한다.
  • 하지만 이 정책 이터레이션 과정은 항상 \(\pi_*\)로 수렴한다.

Policy Improvement Theorem 정책 개선 정리

p.30
theorem

\(\pi\)와 \(\pi'\)가 임의의 결정적 정책 쌍일 때,

\[q_\pi(s, \pi'(s)) \ge v_\pi(s) = \sum_a \pi(a\mid s)\, q_\pi(s,a)\quad \forall s \in \S \;\;\Longrightarrow\;\; v_{\pi'}(s) \ge v_\pi(s)\quad \forall s \in \S\]
proof
\[\begin{aligned} v_\pi(s) &\le q_\pi(s, \pi'(s)) = \E_{\pi'}[q_\pi(s, A_t) \mid S_t = s] \\ &= \E_{\pi'}[R_{t+1} + \gamma v_\pi(S_{t+1}) \mid S_t = s] \\ &\le \E_{\pi'}[R_{t+1} + \gamma q_\pi(S_{t+1}, \pi'(S_{t+1})) \mid S_t = s] \\ &= \E_{\pi'}[R_{t+1} + \gamma\, \E_{\pi'}[R_{t+2} + \gamma v_\pi(S_{t+2}) \mid S_{t+1}, A_{t+1}] \mid S_t = s] \\ &= \E_{\pi'}[R_{t+1} + \gamma R_{t+2} + \gamma^2 v_\pi(S_{t+2}) \mid S_t = s] \\ &\le \E_{\pi'}[R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots \mid S_t = s] = v_{\pi'}(s). \quad\blacksquare \end{aligned}\]
한 줄 요약“한 스텝만 \(\pi'\)를 따르고 나머진 \(\pi\)를 따라도 손해가 없다면, 계속 \(\pi'\)를 따르면 더 좋다.”

Why Policy Iteration Reaches \(\pi_*\) 수렴 논리

p.31 – 32

3장의 정리(\(q_\pi(s^*,a^*) \ge v_\pi(s^*)\)이면 그 상태만 바꾼 정책이 더 좋다)를 모든 상태에 동시에 적용한 게 그리디 개선이에요.

  • \(\pi'(s) = \argmax_{a \in \A} q_\pi(s,a)\) 로 개선. 그러면 \(q_\pi(s,\pi'(s)) = \max_a q_\pi(s,a) \ge v_\pi(s)\) → 정책 개선 정리에 의해 \(v_{\pi'} \ge v_\pi\).
  • 결정적 정책은 유한 개이고, \(\pi' = \pi\)가 될 때까지 매 단계가 엄격히 개선되므로 유한 번 안에 끝난다.
  • 개선이 멈추면:
    \[q_\pi(s, \pi'(s)) = \max_{a \in \A} q_\pi(s,a) = q_\pi(s, \pi(s)) = v_\pi(s)\]
    → 이건 바로 벨만 최적 방정식 \(v_\pi(s) = \max_a q_\pi(s,a)\)!
  • 따라서 모든 \(s\)에 대해 \(v_\pi(s) = v_*(s)\) (유일한 고정점이니까), 즉 \(\pi\)는 최적 정책.

Generalized Policy Iteration GPI

p.33
  • Policy evaluation: \(v_\pi\) 추정 — 어떤 정책 평가 방법이든
  • Policy improvement: \(\pi' \ge \pi\) 생성 — 어떤 정책 개선 방법이든

평가를 끝까지(수렴까지) 하지 않고 몇 번만 해도 되고, 개선을 그리디가 아닌 다른 방식으로 해도 돼요. 평가와 개선이 서로 밀고 당기다 결국 \(v_*, \pi_*\)에서 만나는 이 큰 틀을 GPI라고 불러요. → 5장 MC 제어, 6장 SARSA도 전부 GPI!

part 4value iteration

Value Iteration 개선 + 평가를 한 번에

p.35

결정적 정책을 \(\mu\)라고 하면 (π: stochastic, μ: deterministic), 정책 이터레이션의 두 단계는

\[\textbf{Improvement: }\ \mu(s) = \argmax_a \sum_{s'} p(s'\mid s,a)\{r(s,a,s') + \gamma V_k(s')\}\]
\[\textbf{Evaluation: }\ V_{k+1}(s) = \sum_{s'} p(s'\mid s,\mu(s))\{r(s,\mu(s),s') + \gamma V_k(s')\}\]

그런데 \(\mu(s)\)는 괄호 안을 최대화하는 \(a\)니까, evaluation 식에 대입하면 그냥 그 최댓값이에요. 합치면:

value iteration update
\[V_{k+1}(s) = \max_a \sum_{s'} p(s'\mid s,a)\{r(s,a,s') + \gamma V_k(s')\}\]
필기여기엔 명시적인 policy가 없다! 정책 개선과 평가를 한 번의 max 연산으로 해결.

Find Optimal Value Function using DP

p.36

\(k\)-스텝 최적 기대 리턴:

\[V_k(s) = \max_\pi \E_\pi\Big[\sum_{i=0}^{k-1}\gamma^i R_{t+1+i} \;\Big|\; S_t = s\Big]\]
\[V_k(s) = \max_a \sum_{s'} p(s'\mid s,a)\big[r(s,a,s') + \gamma V_{k-1}(s')\big], \qquad \lim_{k\to\infty} V_k(s) = v_*(s)\]
  • Substructure: 최적 \(k\)-스텝 리턴 = 가장 좋은 첫 행동의 보상 + 다음 상태의 최적 \((k-1)\)-스텝 리턴 (최적성의 원리, principle of optimality)
  • Table structure: \(V_{k-1}(s')\)는 한 번 계산되어 여러 \(s\)가 재사용
  • Bottom-up: \(V_0 \equiv 0\)에서 \(V_1, V_2, \dots\)
수렴 근거3장에서 증명한 대로 벨만 최적 연산자 \(T\)는 \(\gamma\)-축약사상 (p.37 증명 동일) → 바나흐 고정점 정리 (p.38) → 벨만 최적 방정식은 고정점 \(v_*\)를 정의하고 \(V_k \to v_*\).

part 5asynchronous dp

Asynchronous Dynamic Programming 비동기 DP

p.51
  • 지금까지의 DP는 동기식(synchronous) 백업 — 모든 상태를 병렬로(한꺼번에) 백업.
  • 비동기 DP는 상태를 개별적으로, 아무 순서로나 백업.
  • 선택된 각 상태에 적절한 백업을 적용.
  • 계산량을 크게 줄일 수 있다.
  • 모든 상태가 계속 선택되기만 하면 수렴이 보장된다.

Prioritized Sweeping

p.53

벨만 오차(Bellman error)의 크기로 어떤 상태를 먼저 갱신할지 정해요:

\[\Big|\max_{a \in \A} \sum_{s' \in \S} p(s'\mid s,a)\big[r(s,a,s') + \gamma v(s')\big] - v(s)\Big|\]
  • 오차가 큰 상태 = 아직 값이 많이 틀린 상태 → 우선 백업
  • 우선순위 큐로 관리하고, 백업 후엔 영향을 받는 상태(선행 상태)들의 오차를 다시 계산
  • FrozenLake에서도 동기식(k=6) 대비 훨씬 적은 백업으로 같은 결과(k=1에 최적값)에 도달

Self-check 스스로 확인하기

DP의 세 가지 성질은?
Substructure(부분문제로 분해), Table structure(해를 저장해 재사용), Bottom-up computation(작은 문제 → 큰 문제).
반복적 정책 평가와 가치 이터레이션의 업데이트 식 차이는?
정책 평가: \(\sum_a \pi(a\mid s)\sum_{s'}p[r+\gamma V_k(s')]\) (기대 백업). 가치 이터레이션: \(\max_a \sum_{s'}p[r+\gamma V_k(s')]\) (최적 백업).
정책 이터레이션이 유한 번 안에 끝나는 이유는?
결정적 정책의 수가 유한(\(|\A|^{|\S|}\))하고, 매 반복마다 정책이 엄격히 개선되거나(같은 정책 재방문 불가) 멈추기 때문.
FrozenLake 무작위 정책 평가에서 \(V_1(14)\)는? 가치 이터레이션에서는?
정책 평가: \(0.25 \times 10 = 2.5\). 가치 이터레이션: \(\max = 10\).
FrozenLake 최적 가치 \(v_*(0) = 5.9\)는 어떻게 나온 값인가요?
시작점에서 목표까지 6스텝, 마지막 스텝에서 보상 10 → \(10 \times 0.9^5 = 5.905\).
비동기 DP가 수렴하기 위한 조건은?
모든 상태가 (무한히) 계속 선택되어 백업되어야 한다.
GPI란?
어떤 평가 방법과 어떤 개선 방법이든, 평가와 개선을 번갈아(혹은 섞어) 반복하는 일반적인 틀. PI, VI, MC 제어, SARSA 모두 GPI의 사례.
